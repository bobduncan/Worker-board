## Worker Board — Changes from the original design

The goal has shifted from a detailed monitoring dashboard to a simplified AI worker coordination interface, focused
on three functions: Awareness, Intervention, and Coordination.

### 1. Two tabs instead of one crowded dashboard

Tab 1 — Overview (Awareness & Intervention)
- Show all workers, their current tasks, ETAs, queues, and status.
- Show requests requiring user attention in a prominent For you panel.
- Keep the Today activity timeline.
- Remove the separate Queue, Working folders, and Advice panels.

Tab 2 — Advice & Chat (Coordination)
- Combine AI advice and the main chat into one conversational interface.
- Allow the user to discuss priorities, worker progress, dependencies, and task assignments.
- The AI should have access to worker status, queues, and pending decisions.

### 2. Worker cards become compact horizontal lanes

Each worker gets one horizontal row displaying:
- Worker name and colour-coded status.
- Current task title and progress bar.
- Current action, e.g. "Running tests."
- Prominent ETA, preferably completion time plus remaining duration.
- A visual queue showing the first upcoming task, its approximate duration, and a +2 indicator for additional
  queued tasks.
- Expandable queue to inspect remaining tasks.

Removed: Worker task thumbnails, excessive timing metadata, detailed estimate history, and technical information.
Keep warnings for delays, inactivity, or stale estimates, but display them only when relevant.

### 3. Queue is integrated into each worker

The original design had one shared Queue panel. Instead, each worker owns a visible queue within their lane. This
makes it possible to see what a worker is doing now, what comes next, and how much work is waiting, without
switching between sections.

### 4. "For you" becomes an actionable review inbox

This is now one of the most important parts of the interface, rather than a simple task list. Requests are clearly
categorized:

| Type | What the interface provides |
|---|---|
| Input needed | Question, relevant context, optional visual references, mandatory text response, Send button |
| Verification needed | Description of completed work, screenshots where useful or a link to run the relevant branch locally, verification checklist, Approve/Reject buttons, feedback field |
| Intervention needed | Explanation of the blocker, attempted solutions, and the action required |

For verification, screenshots or a working local test link should provide enough evidence to evaluate the result.
Video previews are not necessary by default. Approval feedback can be optional; rejection should require an
explanation.

### 5. Working folders move into secondary details

Remove the permanent Working folders table. Branch names, commits ahead, uncommitted files, and other Git
information should be accessible through expanded worker details or surfaced when they require attention. The user
shouldn't need to monitor Git metadata to understand progress.

### 6. Today timeline remains

Retain the horizontal activity timeline with one lane per worker, consistent state colours, and task-change
markers. It provides historical context without requiring detailed activity logs to be permanently visible.

### 7. Overall visual direction

- Dark, practical, high-contrast design.
- Fewer panels and less decorative content.
- No worker thumbnails.
- Strong visual emphasis on status, task, ETA, queue, and requests requiring attention.
- Details available on demand rather than permanently displayed.
- Images reserved for decisions and verification where they actually help.

The central design principle: The Overview should tell you what everyone is doing, when they'll finish, what
they'll do next, and where they need you. The For you panel should make it easy to act immediately. Advice & Chat
should help you decide how to coordinate the work.
